# triPilot — 요식(Dining) 파트

SK네트웍스 Family AI 캠프 32기 최종 프로젝트 · 6인 팀 · 2026.08 ~ 2026.10
팀 저장소: [SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM) · 내 PR 목록: [author:hwansj](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN32-FINAL-6TEAM/pulls?q=is%3Apr+author%3Ahwansj)

triPilot은 고객의 여행 일정을 Case로 접수하고, 요식·이동·활동 에이전트 팀이 확인해 변경을 제안하는 모듈형 플랫폼입니다. 이 문서는 제가 맡은 요식 파트만 정리했습니다.

## 문제

일정 속 식당이 그 시각에 실제로 이용 가능한지(영업·휴무·결제·동반 조건) 판정하고, 안 되면 동선 안에서 대체 식당을 제안해야 했습니다.

- 기존 규칙 코드는 고객이 자유롭게 쓴 조건(할랄·아이 동반·카드)을 읽지 못했습니다.
- LLM에 판정을 통째로 맡기면 영업 판정 51개 중 26개만 맞혔습니다.

## 구조

```
고객 문장 ──▶ LLM: 확인할 항목 고르기 · 도구 부르기
                     │
                     ▼
            MCP 도구 (규칙 6 · 조회 3)
            영업시간 · 휴무 · 결제 · 동반 · 장소 찾기 …
                     │
                     ▼
            서버 근거 검증 ── 판정이 그 판정을 낸 도구 결과를 인용했는가?
                     │            아니면 "확인 필요"
                     ▼
              접수 확인 화면 (승인은 고객)
```

- 도구: `final_project_cs/app/domains/travel_ops/instances/dining/agent_tools.py` (FastMCP 서버 `build_mcp`)
- 에이전트 루프·근거 검증: `final_project_cs/app/domains/travel_ops/instances/dining/agent.py`
- 모델 연결(OpenAI · Ollama 공통 인터페이스): `final_project_cs/app/infrastructure/llm/tool_chat.py`

## 평가

코드 사본을 고정하고 한 번에 실행한 통합 평가(2026-10-20, 코드 채점).
기준: 개발에 쓰지 않은 검증용 일정 40개의 확인 항목 111개 × 3회 = 333회 판정.

| 구성 | 정확도 | macro-F1 |
|---|---|---|
| 규칙만 | 79.3% | 0.603 |
| 에이전트 + 규칙 도구 | **98.5%** (328/333) | **0.977** |

- 규칙 대비 McNemar p = 0.0001 · 닫힌 식당을 허용한 판정 0/66
- 자유문 조건 F1 0.974 (독립 작성 96과제, 규칙만은 재현율 0)
- 모델 비교(같은 도구 인터페이스): gpt-4o-mini 평균 7.0초, 로컬 gemma 152초 → 로컬 모델은 실시간 경로에서 제외

## 평가로 찾아 고친 결함

| 결함 | 원인 | 수정 · 결과 |
|---|---|---|
| 대체 식당이 장소 ID 순으로 골라짐 | 가격 정보가 비어 정렬이 사실상 ID 순 | 동선·브랜드·메뉴 유사도 순위 → 5/17 → 17/17, 홀드아웃 8/8 |
| 잘못된 장소 확정 | 이름 찾기 범위·체인 지점 판단 | 11건 → 0건 |
| "휴무" 도구 결과에도 "영업 가능" 판정이 검증 통과 | 근거 검증이 어떤 근거인지 안 봄 | 판정 종류별 근거 출처를 강제 |
| 실제 접수에서 10턴 안에 안 끝남 | 같은 가게 반복 검색 | 재검색 차단 · 식사 수 맞춤 턴 상한 · 마지막 답 턴 → 7턴 |
| 필수 조건을 선호로 읽음 | 강도 말이 없으면 선호로 처리 | 독립 평가 110건에서 16/210 발견 후 수정 |

평가 데이터는 프롬프트를 고친 세션과 분리해 만들고, 측정 전에 해시로 고정했습니다.
